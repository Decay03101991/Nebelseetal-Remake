1. Control integration damage before adding features.
   Integrate exactly one player action per commit; forbid unrelated cleanup, renaming and formatting.
   Start from a clean working tree; record HEAD and inspect the target callback plus every state field it reads or writes.
   Write the callback contract first: inputs, module call, changed fields, rejected-action behavior, UI refresh and save behavior.
   Reject an action before mutation if any requirement fails; test that rejection leaves resources, timers and inventory unchanged.
   Trace each integration from a real GUI action through the module to displayed state and save/reload; reject import-only "integration".
   Block portal spending until one selected settlement supplies all required mana; test that combined insufficient settlements cannot pay.
   Remove invented bot armies from canonical play; isolate any retained values as VORSCHLAG and disable affected actions until resolved.
   Verify children independently: derive expected values from cited manual passages, inspect state deltas and exercise the GUI callback.
   Run run_tests.bat after every step; require completed execution, zero errors, no missing tests and no unexplained change to the 14 Befunde.
   Record commands, exit codes, report paths and the exact verified revision; report skipped GUI or executable checks as NOT VERIFIED.
   Commit only reviewed paths, append the required log line and verify an external leading-doc backup by manifest and file hashes.

2. Keep distinct checklists instead of duplicating existing rules.
   Keep the project skill for stable conventions and navigation; keep current progress exclusively in the handover.
   Keep the implementation plan as ordered acceptance criteria; keep the development log append-only and evidence-linked.
   Add "main-py-integration": callback contracts, state ownership, preconditions, mutation order, refresh points and save compatibility.
   Add "manual-provenance": source path and section, exact supported rule, implementation location, null reason and VORSCHLAG status.
   Add "independent-verification": child claim, child's test method, different coordinator method, observed result and evidence path.
   Add "release-gate": full sweep, GUI smoke paths, old-save fixture, save/reload, clean-folder executable launch and artifact hash.
   Generate a module wiring inventory: module, exported operation, main.py caller, reachable GUI action and verification status.
   Reject "integrated" unless both the reachable caller and observed state transition appear in that inventory.

3. Load a small, ordered context packet for each integration.
   Load the non-negotiable rules first; include no-guessing, cost limits, file ownership and completion gates.
   Load a generated state snapshot next: HEAD, dirty paths, latest verified revision, gate results and unresolved blockers.
   Load a handover capped at one page; include the next action, affected files, exact acceptance criteria and evidence links.
   Load only the relevant manual passages, provenance rows and matching data records; preserve their source identifiers.
   Load the target callback, its direct helpers, state initialization and save serialization; expand only along actual dependencies.
   Load the module's public interface and independent verification checklist before requesting child work.
   Give each child an explicit interface, source excerpts and exactly two permitted new paths; forbid edits elsewhere.
   Regenerate the packet at session start; stop and refresh it when HEAD or relevant file hashes change.
   Keep full main.py, entire test logs, historical chat, completed-task detail, unrelated skills and repeated rule copies OUT.
   Store full evidence on disk; put only failures, changed Befunde and paths into context.

4. Neutralize cheap-model failure patterns mechanically.
   Counter plausible rules with a provenance validator; fail canonical records lacking a citation or explicit null plus reason.
   Counter decorated inventions by rejecting VORSCHLAG records in canonical mode; do not treat the label alone as permission.
   Counter dead wiring with callback-level tests that assert the expected module operation was invoked and its result applied.
   Counter duplicated rules by searching main.py for migrated constants and formulas; review every remaining match.
   Counter happy-path bias with generated boundary cases: just below, exactly at and just above each documented threshold.
   Counter partial mutations with before/after state snapshots for rejected actions and injected save-write failures.
   Counter test-count theatre with a runner manifest; fail on absent files, zero-check files, crashes or incomplete summaries.
   Counter hidden tkinter errors by making report_callback_exception fail the GUI smoke run and retain its traceback.
   Counter scope drift with a diff allowlist and AST checks for changed function names or duplicate definitions.
   Counter stale success claims by binding reports to tested file hashes; invalidate the gate after any code or data edit.
   Counter packaging assumptions by launching the rebuilt executable from a separate directory and verifying save/reload there.
